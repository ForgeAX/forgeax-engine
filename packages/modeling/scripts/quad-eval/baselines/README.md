# Offline quad baselines (design milestone M0)

Instant Meshes, QuadriFlow and QuadWild run outside every repository on eight L4 cases; their output is converted to the
quad-eval `json` producer format and scored with the L4 evaluator only. Nothing in this directory is GPL code: only
converted meshes, manifests and scores are committed. Tests never need an external tool.

## Layout

| Path | Content |
|:--|:--|
| `config.ts` | tools, cases, target face counts, shared sharp threshold (30 deg, the evaluator's) |
| `convert.ts` | OBJ -> producer JSON (keeps 3/4-gons, reports dropped polygons), SHA-256, triangle input export |
| `run-baselines.ts` | runs a tool on each case, writes `results/<tool>/<case>.json` plus `<case>.manifest.json` (needs the tools) |
| `score-baselines.ts` | scores every converted file with `evaluate`, `sharpEdges`/`sharpCoverage`, `hausdorff`; computes SJ p05; writes `results/results.json` and `results/TABLE.md` |
| `render-baselines.ts` | `renderShape` network + Jacobian per tool, one `contactSheet` per case under `renders/` |
| `__tests__/` | converter tests, committed-result checks, the corrupted-file falsifier, a feature-mesh staleness check |

Reproduce (tools built under `$QB_ROOT`, default `${TMPDIR:-/tmp}/forgeax-quad-baselines`):
`node scripts/quad-eval/baselines/run-baselines.ts [--tool im|qf|qw] [--case <id>]`, then
`node scripts/quad-eval/baselines/score-baselines.ts`, then
`QB_RENDER_OUT=<dir> npx vitest run scripts/quad-eval/baselines/__tests__/render.test.ts`.
A tool whose binary is missing is recorded as `baseline not available` (no output file, no score).

and the dropped-polygon count (zero in every committed run).

## Deviations (read before using any number)

- **QuadWild is not the paper configuration.** The Gurobi ILP is replaced by a HiGHS 1.8.1 based stand-in for the Gurobi
  C++ API written for this harness. `GenConstrAbs` is relaxed to two inequalities, squared terms use secant epigraphs
  (exact at integers), and CoMISo is disabled (`COMISO_FIELD` off). Quality, runtime and failures of this build do not
  establish what the published QuadWild achieves with Gurobi and CoMISo. It is a baseline for this build only.
- **Face counts are not matched exactly.** Instant Meshes `-f` is approximate; QuadriFlow only takes a target; QuadWild has no
  face target (edge length = average edge x `scaleFact`), so the runner does one calibration run and one corrected run
  (`scaleFact` is in the manifest) and reports the second. Every table row shows actual faces next to the target; the
  largest gaps are QuadriFlow on the sphere (407 vs 600) and the pipe tee/QuadWild (3223 vs 3000). Compare quality
  per face with that in mind.
- **Sharp thresholds differ.** The evaluator counts dihedral above 30 degrees. Instant Meshes gets `-c 30` and QuadWild
  `sharp_feature_thr 30`; QuadriFlow's `-sharp` has a threshold hard-coded at 60 degrees in upstream source (not changed). QuadriFlow therefore
  may legitimately ignore features between 30 and 60 degrees. Instant Meshes `-c` is a crease angle for its field, not a
  hard constraint.
- **Runtime** is wall time on a shared 32-thread server, tools ran one at a time under `forgeax-heavy --low`, QuadWild with OpenMP. The `s`
  column is the reported (second) QuadWild run only; the calibration run roughly doubles the total (`totalWallSeconds` in `results.json`).
- Inputs are the L4 reference meshes (quads split along the shorter diagonal, triangles kept), unrelated to the tools'
  preferred input. The three feature models F1-F3 are generated by our own kernel (`../feature-models.ts`) and are license clean.
- One run per case, no seeds varied except QuadriFlow's fixed seed 1: these are single observations, not distributions.

## Where each tool fails (observations on these eight cases, from the table and the sheets)

- **Instant Meshes** is by far the fastest (under a second) but is the least reliable on features and poles. It folds elements on
  4 of 8 cases (13 inverted quads in total; SJ min below zero on sphere, cylinder, pipe tee and, at exactly 0, F1/F3), it creates
  the most singularities (466 across the eight cases, 217 on the pipe tee, with valences up to 9 and some valence 2), and its sharp-edge
  coverage on feature cases is 3.5-28 percent: the cylinder rim and the fandisk chamfer are cut by
  quads rather than followed. The pipe tee output also has 8 open edges.
- **QuadriFlow** has fewer poles than Instant Meshes (228 in total, only valence 3 and 5) and a clean network away from features, but it
  also folds elements on 4 of 8 cases (34 inverted quads, worst on the pipe tee with 20 and SJ min -0.94 and on F3 at -1.0). Sharp
  coverage is 19-34 percent on feature cases, with the 60 degree caveat above. Face counts undershoot (407 vs 600 on the sphere).
  On the cylinder the cap/side boundary is not followed: the sheet shows a rotated seam and elements stretched across the rim.
- **QuadWild (this HiGHS/no-CoMISo build)** is the only tool with no inverted element on any case (SJ min 0.22-1.0), the fewest poles (152 in total;
  8 on the sphere, cylinder and lumpy sphere) and the best sharp coverage (50-92 percent on the feature cases, 100 percent on the box). It still
  misses features: fandisk covers 50 percent (the chamfer and concave-fillet strip are only partly followed), and the pipe tee has
  64 singularities with a low SJ min of 0.22. It is slow on the largest case (278 s for the reported pipe tee run, about 580 s with
  calibration, against under 40 s on every other case), and it is the one tool whose result depends on the ILP substitute above.
- **None of the three reaches the evaluator's gates on the feature cases.** The L4 gates are SJ min >= 0.3, Hausdorff/diag <= 5e-3 and
  sharp covered >= 0.98: on F1-F3 only QuadWild meets the SJ gate on F1/F3 and the Hausdorff gate on all three feature cases, and no tool
  reaches 98 percent sharp coverage on F1-F3 or the cylinder. That gap is what the replication work is measured against.

## What this does not cover

Only eight cases, one run each; no organic or scanned input; no sizing sweep; QuadWild without Gurobi/CoMISo; no comparison of
equal-singularity or equal-feature settings; Hausdorff is the L4 sample-based estimate. Merged without independent audit.
