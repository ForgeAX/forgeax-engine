## Follow-up implementation: 60-frame windows (2026-09-19)

The requested change is implemented in `codex/ci-heavy-frames-60`, based on
`b212dad8c9c74c1e2fb520fdc3132a6f84d93e5a`. Local validation exercises uncommitted
worktree changes; reports that carry the base HEAD are diagnostic evidence,
not final-commit CI admission.

| Surface | Implemented behavior |
|:--|:--|
| Smoke roster and workflows | 60-frame minimum on PR, push and local paths; reject 59-frame receipts. Duration-to-frame conversion no longer silently restores a 300-frame loop. |
| Expensive rendering tests | Bloom, SSAO, SSR/ReflectionProbe, transmission, shadow, GPU-driven, temporal, material and related browser/Dawn windows use 60; schemas, frame identities and exact partition selectors agree. |
| Lifecycle and animation | Physics observes two fixed steps per render after its unchanged recovery probes, retaining ground contact without additional dropped time. Morph keeps three 20-frame phases; camera input and tilemap mutation remain inside the window; sprite motion retains the animation journey with fewer renders; fog keeps all 20 resizes and 3 recoveries. |
| Bloom motion | 60 samples over x=200..222, maintaining subpixel increments, full-D0 edge checks and the existing 5% energy threshold. The trajectory description derives from the same values as the producer. |
| Performance sampling | 60 measured samples per window; preserve 120 warmup frames, five paired groups, timestamp provenance, nearest-rank P95 and performance thresholds. SSR startup/post-warmup diagnostic windows are now 1..60 and 121..180. |
| Documentation | CI operating guide, active smoke contracts and the Engine debug route use the new frame policy. Historical measurements and archived evidence remain historical. |

The sample-count reduction is 80%; it is **not** a measured 80% CI speedup.
Shader preparation, warmup, asset cooking, queueing and process setup remain.
The shorter performance windows also have lower statistical precision, so a new
comparable full-CI baseline is required before making latency or P95 claims.
