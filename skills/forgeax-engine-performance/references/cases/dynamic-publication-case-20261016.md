# Dynamic publication and evidence admission, 2026-10-16

This Frontline investigation used Engine `b086ca10cdcd77bd6ba60ed1996be735a00cc89c`
and Voxel `38cfffc503737be7fd6221495cc65ba530a999e8`. It does not qualify later
Engine releases. The reusable procedure lives in [Measurement](../measurement.md).
Its formal build explicitly selected the validation-only `webgpu-storage`
material profile. The presentation configuration was complete, but the published
variant closure was not the ordinary portable build; preserve that boundary
when comparing later product builds.

## Withdraw a mechanism when its complete cost is unproven

A shared hidden weapon anchor qualified zero native retransmission and reduced
render entries from 35 to 17. CPU comparison orders disagreed; later review found
asymmetric diagnostic traversal. A revised small owner comparison improved, but
the actual character Rig did not call the new owner's cleanup. The candidate
remained withdrawn: neither a smaller scene representation nor a helper-level
timing proved the application's lifecycle or ordinary FPS benefit.

The retained reports distinguish qualification and CPU order,
observer asymmetry
and missing real cleanup integration.

## Clip CPU to observed coverage

A separate owned Worker CPU diagnostic requested eight seconds. Engine Worker
sampling began 1,403.878 ms after its start acknowledgement; the reliable joined
HUD clip was 6,594.7 ms. Within that clip Host, Engine and Render script samples
were respectively 144.917, 2,790.5535 and 3,859.9615 ms. They overlap and must not
be summed into a frame cost. The clip did not cover the cold first shot.

The CPU report
retains unchanged raw profiles, source mapping, common-clock intersections and
same-capture long gaps. Sampled busy/idle overlap subsequently motivated a read of
the existing two-frame credits; it did not prove that deeper pipelining was absent
or would improve throughput. Actual admission and acknowledgement events remain
necessary before changing that scheduling boundary.

## Separate moved work from removed work

A later same-build portable experiment on Engine
`40aea944ebb79943eafbd77a1316c4ffc664a2ed` isolated transient VFX view work in a
child graph. Parent compiles fell from 615 to 1, but the child still built and
compiled 617 times. Its build timer was 822.6 ms versus the old parent's
893.7 ms; these overlapping owner spans are not an additive CPU saving.
Instrumented completed throughput was 22.5166 versus 22.5312 FPS. The candidate
remained off by default, without an FPS benefit claim.

The first portable diagnostic
also retains failed mesh exports and missing real retirement evidence. A
diagnostic export failure must not skip the application's cleanup. Preserve
bounded partial records and dropped counts; do not enlarge the cap just to
make qualification green.

Lifetime geometry counters initially suggested 2.85 GB versus 0.87 GB of
preparation. The baseline already contained 3,235 prepared but unaccepted inputs
before the firing handshake. Actual firing-window deltas were about 557 MB in
both arms, with every prepared candidate accepted. Separate startup admission
from steady work before selecting a producer optimization. Batch count,
coalesced mesh count and logical bytes are outcomes; exact source edits, actors
and committed cells identify the input workload.

## Profile the complete owner before selecting a small cache

An owned-program entrypoint/layout lookup cache passed its contracts, but two
complete dynamic-owner CPU pairs changed by -3.82% and +1.25%. It was withdrawn.
One subsequent Node/V8 baseline sampled the real stock gun/surface producer,
publication, transfer clone, receiving Null Renderer and source feedback while
replacing an actual mesh every frame. Loading, initial preparation and final
disposal were outside its conservative 2,157.3 ms work core; the measured clock
offset uncertainty was 12.47 ms. This is source-owner attribution, not browser
Worker or GPU acceptance.

The firing frames averaged 1,134 resource declarations but only four compute
programs. Mutually exclusive sample groups attributed 2.83% to declaration
validation, 7.55% to signature capture and 10.09% to pass projection/resolution.
This explains why removing a small lookup could not remove most owner work.
The existing emitter lifecycle supplies a larger candidate boundary: admit an
owned recipe once while keeping roster, resource replacement, uploads and all
draw/dispatch values current. That candidate still requires complete-owner net
benefit, failure/recovery and actual product evidence; these percentages are not
a promised removable-time budget.

The first namespace/prepared-reference recipe slice then passed 56 focused
contracts and preserved all 160 frame outputs, changing mesh bytes, one/two
FixedUpdates, full authored local/remote effects, completion feedback and actual
retirement. Its sustained complete-owner CPU nevertheless regressed by 2.90%
and 2.93% in the two orders. Runtime changes were withdrawn before SDK or Game
integration. Reducing repeated metadata operations did not establish that the
remaining recipe lookup and validation cost was cheaper. Preserve the negative
patch and receipts; do not expand tests or rebuild the whole product to rescue
an already negative owner experiment.

## Reduce the resource population at its producer

The next candidate grouped stock instance buffers into fixed aligned slabs by
cooked program, runtime generation, scope, role, size and usage. Each Player
kept its independent slot, seed, transform, clock, reset and completion feedback;
transparent draws stayed ordered. Live slots did not move when the roster grew.
Provider and custom resources retained their ordinary path.

| Complete dynamic Node owner | Individual buffers | Instance slabs |

| Mean firing-frame declarations | 1,133.71 | 515.57 |
| Mean firing-frame buffers | 715.09 | 96.96 |
| Peak allocated buffer bytes | 7,103,584 | 11,510,008 |

The two sustained work-CPU pairs improved 14.94% and 16.73%. All 160 normalized
frame outputs, actual changing mesh publication, 15,476 dispatches, 7,092 draws,
27,755 writes and 16,757,720 written bytes matched. Both arms disposed every
buffer. These are source/Null owner results, with a measured memory increase;
native GPU slot reads, pixels, normal built-package execution and product FPS
still required separate qualification. The [owner report](../../../../packages/vfx-render/reports/stock-instance-arena-owner-20261016.json)
retains that boundary and the initial failed copy-alias arm.

Suballocation must preserve physical alias identity in the graph. Deduplicate
identical physical copy-access declarations without dropping or reordering copy
commands; incompatible roles still fail. Keep vertex/index/indirect offsets in
the current-frame resolved inputs even when the compiled graph is reused.
Descriptor-only or Null comparisons cannot prove that native shaders read the
intended instance slot.
