# forgeax-engine-wechat

ForgeAX 微信小游戏开发与诊断。适用于通过官方 AI DevTools 构建或运行普通游戏、验证模拟器和真机行为，以及调查原生 UI、渲染、性能与内存。

准确的官方 CLI 契约以腾讯已安装的 `wechatide-skill` 为准。本技能提供 Engine 集成、可复用工具和经过实测的诊断方法。从相关行开始；Sources 中的历史观察是限定范围的结果，不要求重复所有既往实验。

## 以实际游戏为权威

确认 `compileType: "game"`、DevTools 主机上的工程路径、AppID 和预期目标。复用已提供的值。阅读已安装官方技能的版本，检查状态，并通过其 UI 完成实际登录及客户端设置。二维码需要用户处理时，显示真实图片并发送明确的输入通知；只有进度图片可能被忽略。

通过负责该功能的 Engine 或 DevKit 生产器构建。保留完整匹配的 WASM、glue、来源信息及产物清单。导入成功、预览上传、夹具或独立 GL fence，都不能替代普通 App/World/Catalog 路径及 Renderer 完成的场景帧。

选择能复现失败且成本最低的环境。使用硬件 WebGL 的 Mac 浏览器可加速所属模块修复；官方模拟器验证其原生 Host，手机验证自身运行时与驱动。仅手机发生的失败需要直接手机证据，不绕行未变化的模拟器。每项结果记录实际目标和后端，并遵循用户当前优先级。

默认迭代顺序：所属模块回归测试 → 官方模拟器中的完整普通游戏 → 手机。共享 CPU 工作、Bundle 验证和启动逻辑，应先本地复现，再开始另一轮漫长的手机周期。模拟器路径正常后，用手机验证原生下载与网络、设备 GPU、触控、生命周期和最终 FPS；模拟器吞吐不能证明手机预算达标。若已证实仅手机失败，保留模拟器对照，直接诊断失败目标。

没有明确启动或资产原因的渲染失败，遵循 [forgeax-engine-rhi-debug](../forgeax-engine-rhi-debug/SKILL.zh-CN.md)：先捕获失败帧，检查工作和资源，再进行推测性着色器修改。性能问题先建立 Host 资源余量和可重复负载；分别开展正确性捕获、侵入式分析和无插桩验收。

只保留一个本任务拥有的活动模拟器，不使用时关闭。保留其他会话的工程和手机活动。原生输入前观察前台，目标变化时停止。输入坐标必须对应已审阅的当前截图。

将已复现的所属模块失败转为小范围回归测试；复用未变化的构建与资产。将命令、源码身份、实际交互、已完成帧、原始失败和已审阅截图一起保存。只发布脱敏结果，图片链接必须可访问。账号状态、AppID、设备身份、二维码图片和原始日志保留在跟踪源码之外。

证据缺失时扩展所属诊断入口。收集、有界传输、清理、测试和解释在本目录中一并维护；临时探针成功后，先归入该路径再重复依赖。日常调查不要依赖修改生成代码块或私有全局对象。明确展示不可用能力和未完成报告。
